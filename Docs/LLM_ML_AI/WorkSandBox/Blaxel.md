**Blaxel** — это специализированная облачная платформа, созданная как «инфраструктура для автономных AI-агентов». Её ключевая особенность — предоставление так называемых **«вечных песочниц» (perpetual sandboxes)**: изолированных вычислительных сред, которые могут находиться в режиме ожидания сколь угодно долго и возобновлять работу за считанные миллисекунды.

В отличие от универсальных облачных провайдеров, Blaxel изначально проектировалась под нужды AI-агентов, где основными «пользователями» инфраструктуры являются не люди, а программы.

### ⚙️ Подробное описание Blaxel

Архитектура Blaxel строится вокруг нескольких ключевых компонентов, которые могут использоваться как вместе, так и по отдельности.

*   **Perpetual Sandboxes (Вечные песочницы) — флагманский продукт**: Это микро-VM (на базе Firecracker) с полным доступом к файловой системе, процессам и сети. Главное отличие — интеллектуальный жизненный цикл: после ~5 секунд бездействия песочница автоматически переходит в режим ожидания (standby), сохраняя память, файлы и запущенные процессы. При поступлении нового запроса она возобновляет работу менее чем за **25 миллисекунд**, даже если простояла недели. Это устраняет проблему «холодного старта», характерную для других платформ.
*   **Agents Hosting (Хостинг агентов)**: Позволяет развертывать код AI-агента как бессерверный (serverless) эндпоинт с автоматическим масштабированием. Blaxel не навязывает фреймворки — вы просто предоставляете код, а платформа сама собирает и запускает его.
*   **Batch Jobs (Пакетные задания)**: Масштабируемый вычислительный движок для фонового выполнения множества параллельных AI-задач, которые агент может запланировать.
*   **MCP Servers Hosting**: Развертывание серверов инструментов (Model Context Protocol) для расширения возможностей агентов, с низкой задержкой запуска.
*   **Хранилище (Storage)**: Предлагает три уровня для разных нужд: **файловая система песочницы** (самая быстрая, но недолговечная), **Volumes** (надежное блочное хранилище для одного пользователя) и **Agent Drive** (общая файловая система для совместного доступа нескольких агентов).
*   **Model Gateway (Шлюз моделей)**: Единая точка маршрутизации запросов к LLM от разных провайдеров с встроенной телеметрией, контролем затрат на токены и возможностью fallback (переключения при сбое).
*   **Сетевая инфраструктура**: Управляемые кастомные домены, прямые preview-URL для доступа к песочницам и выделенные egress-шлюзы для контроля исходящего трафика.

**Важный контекст:** В сентябре 2026 года Blaxel была приобретена компанией Baseten, но продолжает продаваться и развиваться как самостоятельный продукт.

### 📊 Сравнение с аналогами

Прямыми конкурентами Blaxel являются другие платформы для выполнения AI-генерируемого кода и агентных рабочих нагрузок. Ключевые различия лежат в плоскости жизненного цикла песочниц, сетевых возможностей и модели развертывания.

| Характеристика | **Blaxel** | **E2B** | **CodeSandbox** | **Beam** | **Koyeb** |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Основной фокус** | Инфраструктура для production-агентов (песочницы + хостинг) | Открытая инфраструктура песочниц с возможностью self-hosting | Браузерная среда разработки (приобретена Together AI) | Serverless-платформа с фокусом на GPU-нагрузки | Serverless-платформа для глобальных приложений |
| **Модель изоляции** | Firecracker microVM | Firecracker microVM | Firecracker microVM | gVisor / runc (общее ядро) | Не указано (контейнеры) |
| **Жизненный цикл / Возобновление** | **Автоматический standby** после ~5 сек, возобновление **<25 мс** с сохранением памяти | Настраиваемая пауза, возобновление ~1 сек (документировано) | Режим гибернации, возобновление **1–3 сек** (из архива дольше) | Не является ключевой особенностью | Не является ключевой особенностью |
| **Длительность standby** | **Неограниченно** (на высоких тарифах) | Неограниченно (пока не удалена) | До **7 дней** на диске | — | — |
| **Сохранение состояния** | **Память, процессы, ФС, env** | Память и ФС (по умолчанию) | Снапшот памяти | — | — |
| **Кастомные домены** | ✅ **Управляемые** | ❌ (требуется свой reverse-proxy) | ⚠️ Только предустановленные `csb.app` | — | — |
| **Self-hosting / BYOC** | ⚠️ Только управляемый control plane | ✅ **Открытый исходный код**, BYOC в AWS/GCP/Azure | ❌ (облачный сервис) | — | ✅ (глобальное развертывание) |
| **SDK / Языки** | Python, TypeScript, Go | JS, TS, Python (+ исполнение R, Java, Bash) | TypeScript | — | — |
| **Бесплатный тариф / старт** | Нет base fee, оплата по факту | **Hobby-план с кредитом $100** | Есть бесплатный план | — | Есть бесплатный план |
| **Безопасность / Комплаенс** | SOC 2, **ISO 27001**, SAML, SCIM, HIPAA BAA | SOC 2 Type II | SOC 2 Type II (на уровне Enterprise) | — | — |

**Когда выбирать не Blaxel (краткий вывод):**
*   **E2B**: Если вам нужен полный контроль над инфраструктурой (self-hosting), поддержка большего числа языков (R, Java) или песочницы с полноценным рабочим столом (Desktop) для задач computer-use.
*   **CodeSandbox**: Если ваша основная аудитория — люди-разработчики, которым нужна браузерная IDE, а не автономные агенты.
*   **Beam / Koyeb**: Если ваши задачи смещены в сторону GPU-вычислений (Beam) или развертывания традиционных веб-приложений с глобальным присутствием (Koyeb), а не управления состоянием агентных сессий.

### 💡 Сценарии использования Blaxel

Благодаря своим уникальным характеристикам, Blaxel особенно хорошо подходит для сценариев, где важна длительность сессии и низкая задержка при возобновлении.

1.  **Кодинг-агенты с длительными сессиями**: Пользователь запускает агента для генерации приложения, оставляет его на ночь, а утром возвращается. Благодаря «вечным песочницам» всё состояние (открытые файлы, запущенные процессы, preview) сохраняется, и работа продолжается с того же места, а не начинается заново.
2.  **Агенты для код-ревью**: Агент проверяет пул-реквесты, которые поступают нерегулярно. Между запросами песочница находится в режиме ожидания, за который не взимается плата за вычисления. При появлении нового PR она мгновенно просыпается и приступает к работе.
3.  **Интерактивные данные-пайплайны и RAG-агенты**: Агент выполняет скрипты для извлечения данных из баз или обработки видеофайлов. Возможность запускать код в изолированной среде с сохранением состояния между вызовами делает такие пайплайны эффективными.
4.  **Автономные системы мониторинга (M2M)**: Агенты, которые анализируют видеопотоки с камер, обнаруживают инциденты и генерируют отчеты. Песочницы могут постоянно находиться в режиме готовности, мгновенно реагируя на события.
5.  **Разработка и production-эксплуатация AI-генерируемого ПО**: Blaxel покрывает весь цикл: **Sandboxes** используются для разработки и экспериментов, а **Applications** — для развертывания готового, «замороженного» снимка приложения в качестве публичного эндпоинта с управлением версиями и кастомным доменом.
