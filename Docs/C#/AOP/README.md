**Аспектно-ориентированное программирование (АОП)** — это парадигма, которая позволяет выделить **сквозную функциональность** (cross-cutting concerns) в отдельные модули — **аспекты**. Сквозная функциональность — это логика, которая пронизывает множество несвязанных между собой классов и методов: логирование, кэширование, обработка исключений, транзакции, проверка прав, метрики. Вместо того чтобы дублировать эту логику в каждом методе, АОП «выносит» её наружу и автоматически **вплетает** (weaving) обратно в код в нужных точках.

### 🔑 Ключевые концепции АОП

- **Аспект (Aspect)** — модуль, инкапсулирующий сквозную логику.
- **Совет (Advice)** — действие, которое выполняется аспектом (до, после или вокруг метода).
- **Точка соединения (Join Point)** — место в программе, куда может быть встроен аспект (обычно вызов метода).
- **Срез (Pointcut)** — выражение, определяющее, какие именно точки соединения должен перехватывать аспект.
- **Вплетение (Weaving)** — процесс интеграции аспектов в основной код. Может происходить **во время компиляции** (compile-time, статическое) или **во время выполнения** (runtime, динамическое).

## 💎 Как выбрать подходящий инструмент?

- **Нужна максимальная производительность и не важен бюджет** → **PostSharp** (compile-time, нет overhead на прокси).
- **Бесплатное решение с богатой экосистемой для интерфейсов** → **Castle DynamicProxy** (часто в связке с Autofac).
- **Современный .NET Core проект с async-методами и требованием к производительности** → **AspectCore** (нативная поддержка async, лучшая совместимость с DI).
- **Бесплатное compile-time решение без runtime-зависимостей** → **Fody + MethodBoundaryAspect.Fody**.
- **Легковесный и простой в освоении** → **CZGL.AOP** или **NConcern** (для специфических сценариев инъекции).

Выбор зависит от этапа, на котором вы хотите вплетать аспекты (компиляция или выполнение), от требований к производительности и от того, насколько тесно вы хотите интегрироваться с существующим DI-контейнером.
