Стек **LangChain / LangGraph / LangSmith** — это три уровня экосистемы для создания агентных приложений на базе LLM. Если представить это как завод, то **LangChain** — это конвейер и стандартные детали, **LangGraph** — диспетчерская, управляющая сложной логикой и состоянием, а **LangSmith** — система видеонаблюдения и контроля качества, показывающая, что происходит на каждом этапе.

### 🧩 LangChain: Интеграции и абстракции

**Для чего нужен:** Это фундаментальный слой, который решает проблему «зоопарка» LLM-провайдеров. Вместо того чтобы писать разный код для OpenAI, Anthropic или GigaChat, вы используете единый интерфейс. LangChain предоставляет стандартные «кирпичики» для построения цепочек (chains): шаблоны промптов, обертки для моделей, парсеры вывода и инструменты для работы с внешними данными (RAG).

**Как использовать:** Вы собираете приложение как линейную или DAG-последовательность (направленный ациклический граф). Например, цепочка для ответа на вопрос по документам: *Получить вопрос → Найти релевантные куски в векторной базе → Сформировать промпт с контекстом → Отправить в LLM → Распарсить ответ*. Для этого используется LCEL (LangChain Expression Language) — декларативный синтаксис вроде `prompt | model | parser`.

**Когда достаточно:** Для простых линейных задач, чат-ботов с памятью, базового RAG. Если логика не требует циклов, ветвлений и сложной координации.

### 🕸️ LangGraph: Оркестрация и состояние

**Для чего нужен:** LangChain хорош для «прямых» процессов, но ломается, когда агенту нужно *думать*, *возвращаться*, *исправлять* и *ветвиться*. LangGraph — это низкоуровневый фреймворк для оркестрации таких «умных» агентов. Он представляет рабочий процесс как **граф**: узлы — это действия (вызов LLM, вызов инструмента, код), а ребра — это переходы между ними. Главное отличие от простых цепочек — поддержка **состояния** и **циклов**.

**Как использовать:** Вы определяете состояние (например, список сообщений, промежуточные результаты), добавляете узлы (функции, которые что-то делают и обновляют состояние) и соединяете их ребрами. Ребра могут быть условными: например, «если модель запросила инструмент — идем в узел `call_tool`, если ответила — идем в `finish`». Это позволяет строить мультиагентные системы (например, супервизор, который направляет задачи разным агентам), реализовывать Human-in-the-loop (прерывание для подтверждения человеком) и сохранять прогресс при сбоях (durable execution).

**Когда нужен:** Для сложных агентов с многошаговым планированием, циклами (agent loop), мультиагентными системами и требованиями к надежности.

### 🔍 LangSmith: Наблюдаемость и оценка

**Для чего нужен:** LLM-приложения недетерминированы. Агент может пойти не туда, потратить лишние токены или сломаться на 10-м шаге. LangSmith — это платформа, которая записывает **трассы** (traces) выполнения: какой промпт ушел в модель, что она ответила, какой инструмент вызвала, что он вернул, сколько времени и денег это заняло. Без этого отладка агентов превращается в гадание.

**Как использовать:** Достаточно задать переменные окружения (`LANGSMITH_TRACING=true`, `LANGSMITH_API_KEY`), и LangChain/LangGraph-приложения автоматически начнут логироваться. В интерфейсе LangSmith вы видите дерево вызовов, можете открыть любой узел, посмотреть его вход/выход, поиграть с промптом в Playground и запустить оценку (evaluation) на наборе тестовых данных, чтобы сравнить версии приложения.

**Важно:** LangSmith может работать не только с LangChain/LangGraph. Он поддерживает интеграции с CrewAI, PydanticAI, Vercel AI SDK и даже с «голым» OpenAI SDK через обертки (`wrap_openai`).

### 🆚 Аналоги и альтернативы

Хотя LangChain — де-факто стандарт, у него есть альтернативы на каждом уровне.

**Аналоги LangChain (Фреймворки абстракций):**
*   **LlamaIndex:** Сильный конкурент, фокусирующийся в первую очередь на **RAG** и работе с данными. Считается более удобным для задач индексации и поиска, чем LangChain.
*   **Haystack (deepset):** Промышленный фреймворк для построения поисковых и RAG-систем, с акцентом на надежность и production-готовность.
*   **Semantic Kernel (Microsoft):** Аналог для экосистемы .NET/C#, хотя есть версии для Python и Java.

**Аналоги LangGraph (Оркестрация агентов):**
*   **CrewAI:** Фреймворк для мультиагентных систем, где агенты описываются ролями («исследователь», «писатель») и работают как команда. Проще в освоении для командных сценариев, но менее гибок в контроле графа.
*   **AutoGen (Microsoft):** Фреймворк для мультиагентных систем, построенный вокруг диалога между агентами. Хорош для исследовательских задач, но может быть сложнее в продакшене.
*   **Claude Agent SDK (Anthropic):** Нативный SDK для создания агентов на Claude с первоклассной поддержкой MCP (Model Context Protocol). Если вы жестко привязаны к Claude, это может быть проще и производительнее.
*   **OpenAI Agents SDK:** Аналогичный инструмент для экосистемы OpenAI с поддержкой handoffs (передачи задач между агентами).

**Аналоги LangSmith (Наблюдаемость):**
*   **Langfuse:** Популярная open-source альтернатива. Можно развернуть у себя (self-hosted), что критично для проектов с требованиями к резидентности данных (например, EU или РФ).
*   **Arize Phoenix:** Также open-source инструмент для трассировки и оценки LLM-приложений, часто используется в связке с Langfuse или самостоятельно.
*   **Weights & Biases (W&B) Weave:** W&B известны в MLOps, их продукт Weave фокусируется на наблюдаемости и оценке LLM-приложений.

### 🇷🇺 Российский контекст

Для российского стека важна адаптация под локальные модели и требования к данным:
*   **GigaChain:** Это набор интеграций (например, `langchain-gigachat`), который позволяет использовать **GigaChat** как модель внутри LangChain/LangGraph. Вы можете строить агентов по мировым стандартам, но с российской LLM.
*   **Deep Agents (от Сбера):** Обвязка (harness) поверх LangGraph, которая добавляет готовые инструменты для планирования, работы с файловой системой и управления контекстом. 
*   **Аналоги наблюдаемости:** Для self-hosted трассировки можно использовать Langfuse или Arize Phoenix, развернутые в контуре компании, чтобы данные не уходили за рубеж.

Если вы только начинаете, логичный путь: **LangChain** для базового прототипа → **LangGraph**, когда нужна сложная логика → **LangSmith** (или self-hosted аналог), когда нужно понять, почему агент сломался.
