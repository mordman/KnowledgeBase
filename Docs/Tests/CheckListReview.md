# Обобщённый чек-лист качества тест-кейса (review checklist)

Назначение: проверить, что **каждый тест-кейс правильно заполнен и ничего не забыто** — перед импортом в TestRail, перед ревью, перед передачей в автоматизацию.

Применяется к каждому кейсу индивидуально. Если хотя бы один пункт блока A не выполнен — кейс не принимается.

---

## Блок A. Обязательные поля (must-have, без них кейс не валиден)

- [ ] **`TestID`** заполнен, уникален, соответствует формату `TC-<Домен>-<Номер>` (например, `TC-PORT-004`)
- [ ] **`Title`** заполнен, отражает суть проверки (не «проверка кнопки», а «стоп-аут срабатывает при падении цены»)
- [ ] **`Type`** заполнен, значение из справочника (`Functional`, `UI`, `API`, `Negative`, `Performance`, `Security`, `Compatibility`, `Regression`, `Usability`, `Localization`)
- [ ] **`Priority`** заполнен, значение из справочника (`Critical`, `High`, `Medium`, `Low`)
- [ ] **`Preconditions`** заполнены — что должно быть готово до шагов (данные, состояние счёта, роль, окружение)
- [ ] **`Steps`** заполнены — последовательность действий, каждый шаг пронумерован
- [ ] **`ExpectedResult`** заполнен — конкретный проверяемый результат (не «работает корректно»)
- [ ] **`RequirementID`** заполнен, значение `BRQ-*`, существует в реестре требований
- [ ] **`LinkedIssue`** заполнен, значение `STORY-*`, существует в трекере
- [ ] **`Status`** заполнен (`Not Run` / `Passed` / `Failed` / `Blocked` / `Skipped`)

---

## Блок B. Качество содержания (must-have для приёмки)

### B.1. Название (`Title`)
- [ ] Название описывает **что проверяется**, а не **как** (не «нажать кнопку», а «перевод исполняется при достаточном балансе»)
- [ ] Нет общих слов: «проверка», «тест», «работает», «корректно»
- [ ] Уникально в пределах набора — нет двух кейсов с одинаковым названием
- [ ] Понятно человеку, не читавшему шаги

### B.2. Предусловия (`Preconditions`)
- [ ] Указаны **данные** (баланс, тикер, роль, лимит)
- [ ] Указано **состояние системы** (авторизован, заявка активна, вклад открыт)
- [ ] Указано **окружение** (Web / Mobile / API / Perf stand)
- [ ] Указаны **зависимости** (какая фича/модуль уже готовы)
- [ ] Нет отсылок «см. другой кейс» без явного указания

### B.3. Шаги (`Steps`)
- [ ] Каждый шаг — **одно действие** (не «открыть и выбрать»)
- [ ] Шаги пронумерованы
- [ ] Указаны **конкретные значения** (не «ввести сумму», а «ввести 10 000 ₽»)
- [ ] Указаны **селекторы/поля** (не «нажать кнопку», а «нажать „Подтвердить“»)
- [ ] Порядок шагов воспроизводим (другой человек повторит 1:1)
- [ ] Нет пропущенных шагов (переход между экранами, подтверждение SMS)
- [ ] Шаги не дублируют предусловия

### B.4. Ожидаемый результат (`ExpectedResult`)
- [ ] Результат **проверяемый** (число, статус, сообщение, запись в БД, лог)
- [ ] Указано **что** проверять (UI, БД, API-ответ, лог, уведомление)
- [ ] Указано **где** проверять (экран, история, аудит)
- [ ] Нет формулировок «работает корректно», «без ошибок», «успешно»
- [ ] Результат соответствует требованию (`RequirementID`)
- [ ] Учтены **побочные эффекты** (комиссия, уведомление, запись в историю)

---

## Блок C. Трассируемость (must-have для аудита)

- [ ] `RequirementID` существует в реестре требований (нет orphan BRQ)
- [ ] `LinkedIssue` существует в трекере (нет orphan STORY)
- [ ] `LinkedIssue` действительно реализует `RequirementID` (связь `STORY → BRQ` корректна)
- [ ] Кейс не покрывает несуществующее требование
- [ ] Кейс не привязан к закрытой/отменённой истории без пояснения
- [ ] Полная цепочка `BRQ → STORY → TC` восстанавливается (Q15)
- [ ] В матрице трассируемости нет дублей `TestID`

---

## Блок D. Автоматизация (must-have перед передачей в авто)

- [ ] `AutomationStatus` заполнен (`Auto` / `Manual` / `ToDo` / `Skipped`)
- [ ] Если `Auto` — `AutomationScript` заполнен и указывает на существующий файл/функцию
- [ ] Если `Auto` — скрипт запускается локально и в CI
- [ ] Если `Auto` — есть маркеры `@pytest.mark.requirement/story/testid`
- [ ] Если `Manual` — указана причина (usability, физическое устройство, долгий процесс)
- [ ] `AutomationScript` соответствует `TestID` (не скопирован от другого кейса)
- [ ] В скрипте нет захардкоженных секретов/токенов

---

## Блок E. Данные и окружение

- [ ] `Environment` заполнен (`Web` / `Mobile` / `Desktop` / `API` / `Perf stand`)
- [ ] `Owner` заполнен (кто отвечает за кейс)
- [ ] `Sprint` заполнен (в каком спринте актуален)
- [ ] Данные в шагах не противоречат предусловиям (баланс 1000 ≠ шаг «ввести 50 000»)
- [ ] Указаны тестовые учётки/тикеры, если они специфичны
- [ ] Нет ссылок на прод-данные

---

## Блок F. Негативные и граничные (если применимо)

- [ ] Для позитивного кейса есть парный негативный (хотя бы один)
- [ ] Указаны граничные значения (0, −1, max, max+1)
- [ ] Для API — проверены коды ответов (200/201/400/401/403/404/422/429/500)
- [ ] Для UI — проверены пустые поля, неверный формат, длинные строки
- [ ] Для безопасности — проверены инъекции, IDOR, JWT, tampering (если применимо к домену)

---

## Блок G. Согласованность с набором

- [ ] `TestID` не дублирует существующий
- [ ] Название не дублирует существующий кейс
- [ ] Кейс не противоречит другому кейсу (разные ожидаемые результаты на одно действие)
- [ ] Если кейс заменяет старый — старый помечен `Deprecated` с указанием замены
- [ ] Кейс входит хотя бы в один набор (smoke / regression / platform)
- [ ] `Priority` соответствует критичности требования (`Critical` BRQ → `Critical` TC)

---

## Блок H. Формат и импорт (must-have перед загрузкой в TestRail)

- [ ] Все 17 колонок CSV заполнены (или явно пусты там, где допустимо)
- [ ] Нет лишних пробелов в начале/конце значений
- [ ] Нет переносов строк внутри ячеек CSV (или экранированы)
- [ ] Нет спецсимволов, ломающих CSV (`,`, `"`, `\n`)
- [ ] Кодировка UTF-8
- [ ] `Steps` использует единый разделитель (`->` или `|`)
- [ ] `Priority` и `Type` — из справочника (не «высокий», а `High`)
- [ ] `Status` = `Not Run` для новых кейсов
- [ ] `ActualResult` и `BugID` пусты для новых кейсов

---

## Блок I. Готовность к ревью (финальный gate)

- [ ] Кейс прочитан вслух — звучит однозначно
- [ ] Другой QA может выполнить кейс без вопросов
- [ ] Разработчик поймёт, что проверяется, из названия + ожидаемого результата
- [ ] PO подтвердит, что кейс проверяет именно требование `RequirementID`
- [ ] Кейс не «тестирует всё подряд» — одна проверка на кейс
- [ ] Кейс не «дырявый» — покрывает и happy path, и отказ (если применимо)
- [ ] Нет TODO/FIXME/TBD в тексте
- [ ] Нет ссылок «см. вики» без явного URL

---

## Блок J. Метрика качества кейса (оценка)

Каждый блок = 1 балл (A–I, всего 9). Кейс принимается при **≥ 8/9**.

| Балл | Статус | Действие |
|---|---|---|
| 9/9 | ✅ Ready | Импорт в TestRail |
| 8/9 | ✅ Ready with minor | Импорт, замечания в комментарий |
| 7/9 | ⚠️ Needs fix | Вернуть автору |
| ≤ 6/9 | ❌ Reject | Переписать |

## Как использовать

1. **Перед импортом в TestRail** — прогнать блоки A + H по всем 100 кейсам (автоматически скриптом).
2. **На ревью** — блоки B + C + I (ручное ревью лидом).
3. **Перед передачей в авто** — блок D (проверка скриптов и маркеров).
4. **Перед аудитом** — блок C + G (трассируемость и согласованность).
5. **При добавлении нового кейса** — все 9 блоков.

## Автоматизация проверки (скрипт для CI)

```python
# scripts/review_cases.py
import csv, sys, json

REQUIRED = ["ID","Title","Type","Priority","Preconditions","Steps",
            "ExpectedResult","RequirementID","LinkedIssue","Status",
            "AutomationStatus","Environment","Owner","Sprint"]
ALLOWED_TYPE = {"Functional","UI","API","Negative","Performance","Security",
                "Compatibility","Regression","Usability","Localization"}
ALLOWED_PRIO = {"Critical","High","Medium","Low"}
ALLOWED_AUTO = {"Auto","Manual","ToDo","Skipped"}
FORBIDDEN = ["TODO","FIXME","TBD","работает корректно","без ошибок"]

def review(path):
    errors, seen = [], set()
    for i, r in enumerate(csv.DictReader(open(path, encoding="utf-8")), 2):
        tid = r.get("ID","")
        # A. Обязательные поля
        for f in REQUIRED:
            if not r.get(f, "").strip():
                errors.append(f"row {i} [{tid}] empty field: {f}")
        # G. Уникальность
        if tid in seen:
            errors.append(f"row {i} duplicate ID: {tid}")
        seen.add(tid)
        # H. Справочники
        if r.get("Type") not in ALLOWED_TYPE:
            errors.append(f"row {i} [{tid}] bad Type: {r.get('Type')}")
        if r.get("Priority") not in ALLOWED_PRIO:
            errors.append(f"row {i} [{tid}] bad Priority: {r.get('Priority')}")
        if r.get("AutomationStatus") not in ALLOWED_AUTO:
            errors.append(f"row {i} [{tid}] bad AutomationStatus")
        # B/I. Запрещённые формулировки
        text = (r.get("Title","") + " " + r.get("ExpectedResult","")).lower()
        for w in FORBIDDEN:
            if w.lower() in text:
                errors.append(f"row {i} [{tid}] forbidden phrase: {w}")
        # D. Auto → Script
        if r.get("AutomationStatus") == "Auto" and not r.get("AutomationScript","").strip():
            errors.append(f"row {i} [{tid}] Auto without AutomationScript")
    return errors

if __name__ == "__main__":
    errs = review(sys.argv[1])
    if errs:
        print("\n".join(errs)); sys.exit(1)
    print("OK: all cases pass review checklist")
```

**Запуск:**
```bash
python scripts/review_cases.py cases_100.csv
# exit 0 — все кейсы валидны
# exit 1 — список замечаний
```

| B | Качество содержания | Ревьюер |
| C | Трассируемость | Авто (SQL) + ревьюер |
| D | Автоматизация | Авто + ревьюер |
| E | Данные и окружение | Авто |
| F | Негатив/граничные | Ревьюер |
